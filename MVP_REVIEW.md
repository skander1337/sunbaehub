**SunbaeHub MVP release review — 12 September 2026**

**Decision: GO for a supervised hackathon demonstration with synthetic data; NO-GO for a public launch with real users, CVs, or payments.** The product has enough feature breadth. The remaining work should make the consultation reliable and the trust/payment promises accurate.

Reviewed commit: `b4c9c90`. Application code was not changed. Source/security/business reviews ran independently; UX assessment A was `/root/product_review`, and detector/mobile assessment B was `/root/ui_evidence`.

**Small additions I would prioritize**

1. **Finish the expert activation flow.** Approval currently does not require availability. Add “Set your first available hours” to onboarding, and show the next available slot on discovery cards. A verified profile with no bookable time should have an explicit state. See [admin.ts:7](/Users/personalitaet/Desktop/hackathon/src/lib/services/admin.ts:7) and [specialist dashboard:121](/Users/personalitaet/Desktop/hackathon/src/app/(app)/specialist/dashboard/page.tsx:121).
2. **Booking confirmation and reminders.** Existing notifications are in-app rows. Add an external confirmation and starts-soon reminder with a room link, plus calendar export. A small invited pilot can use manually operated reminders initially. The lifecycle currently runs when somebody loads a page. See [booking.ts:71](/Users/personalitaet/Desktop/hackathon/src/lib/services/booking.ts:71) and [layout.ts:20](/Users/personalitaet/Desktop/hackathon/src/app/layout.tsx:20).
3. **A clear “Something went wrong” flow.** Show exact refund credits and the dispute deadline before review locks settlement. Give admins scoped access to relevant transcript/attachments and show their decision note to both parties. A 100-credit approved refund actually returns 45, while prominent copy says 50%. See [refund.ts:7](/Users/personalitaet/Desktop/hackathon/src/lib/rules/refund.ts:7), [dispute.ts:17](/Users/personalitaet/Desktop/hackathon/src/lib/services/dispute.ts:17), and [review page:42](/Users/personalitaet/Desktop/hackathon/src/app/(app)/bookings/[id]/review/page.tsx:42).
4. **A shared session takeaway.** Add an expert-written card: “What we worked on,” “Three next actions,” and the reviewed attachment. This directly supports the product goal of improving an application. The current post-session artifact is mostly an attendance certificate. This is my preferred new product feature after the blockers.
5. **A usable first-session offer.** New seekers receive 70 credits, but the top listed expert costs 105 for 30 minutes. Provide “Book with your welcome credits” results and display the eligible 30-minute price on cards. Preserve date, time, duration, and note across login. See [SlotPicker.tsx:23](/Users/personalitaet/Desktop/hackathon/src/components/SlotPicker.tsx:23) and [SlotPicker.tsx:184](/Users/personalitaet/Desktop/hackathon/src/components/SlotPicker.tsx:184).

For a public beta, also provide account recovery, a visible support contact, and clear document-publication/retention choices. These are operational prerequisites for the existing account and CV flows, rather than reasons to expand the product.

**Validation and limits**

- Production build and TypeScript compilation passed in an isolated project copy. Two build warnings identify dynamic upload paths that cause whole-project tracing.
- ESLint failed with two errors and two warnings. These are separate from the successful production build.
- A browser smoke test against a fresh isolated database passed seeker login, a 30-minute booking, a 70-credit deduction (680 → 610), session chat submission, early completion, and review submission. A separate seeded 135-credit session settled to specialist 128/platform 7, with one release and one fee row.
- Independent tests against synthetic in-memory databases reproduced verification bypass, pre-start completion, and duplicate payout after an injected failure. A duplicate specialist-slot attempt was correctly rejected.
- Public landing, directory, and profile were visually inspected. Independent mobile inspection at 390×844 found no horizontal page overflow. The focused Impeccable CLI scan returned zero findings; browser inspection still found the header/context issues above. No mutable browser overlay was available; screenshots and read-only DOM dimensions supplied the evidence.
- UX assessment: 24/40 across ten heuristics. Strongest areas were typography, visual consistency, hierarchy, visible pricing, and recognizable actions. Weaker areas were error recovery, promise accuracy, onboarding, and scheduling support. This is a qualitative assessment, not user research.
- The complete existing onboarding and two-browser attachment/translation suites were not rerun. Production hosting, backup/restore, external reminders, real payment integration, and load/concurrency were not validated. Real email verification/password reset do not exist yet.

The next release gate should be a clean build/lint, regression coverage for the reproduced business failures, and a complete new expert → approval → availability → seeker booking → attendance → takeaway → review/refund run. After that, start with a small invited cohort and measure first booking, completed sessions, no-shows, refund requests, and whether the seeker leaves with a useful next action.

Impeccable context also reported a stale landing-page target and an unset design build-path preference. These do not block this review; repointing the brief and choosing a build path can wait for future design work. No clarification was needed for the release recommendation.
